# 架构一页

> 目标：用一页纸说清"这个骨架由哪几层组成、一轮 tick 按什么顺序发生、哪个闸门管哪一段"。
> 读代码时对照 `src/` 的文件名即可。

## 1. 三层 + 一层地基

```
┌──────────────────────────────────────────────────────────────────────┐
│  ① 调度层   scheduler.mjs / registry.mjs / bin/ops-tickd.mjs          │
│     · 谁该跑：三个 job 的注册表 + 到期判定（intervalMs / initialDelayMs）│
│     · 怎么跑：每 job 抢锁 → 跑 → 超时隔离 → 记账（ops-tickd.json）      │
├──────────────────────────────────────────────────────────────────────┤
│  ② 自主层   autonomy.mjs / bin/ops-autonomy.mjs                       │
│     · 能不能动手：mode（observe/report/act）                            │
│     · 动手到哪一步：auto.* 逐项开关（双闸）                             │
│     · 写盘必带 by/why，并落一行审计                                     │
├──────────────────────────────────────────────────────────────────────┤
│  ③ 通知层   notify.mjs / jobs/queue-notify.mjs / alert.mjs            │
│     · 业务通知：读 ops-queue.json → 去重 → 默认写本地 outbox           │
│     · 组件告警：ops-alert.log（出问题的是骨架自己）                     │
├──────────────────────────────────────────────────────────────────────┤
│  地基     store.mjs（原子写/锁）· audit.mjs（哈希链）· paths.mjs（路径）│
└──────────────────────────────────────────────────────────────────────┘
```

三层是**单向依赖**：调度层可以调用自主层与通知层；自主层只读状态、不知道谁在调度；
通知层不知道调度周期。地基谁都能用，但地基不 import 上面任何一层（避免循环依赖）。

## 2. 一轮 tick 的时序

```
ops-tickd --once
  │
  ├─ 读 ops-autonomy.json（缺则按默认建，全关 / observe）
  │
  ├─ for job in [queue-notify, self-heal, daily-report]:      ← 顺序有意：日报必须最后
  │     ├─ 抢锁 ops-locks/tickd-<job>.lock（wx 原子；抢不到 = 跳过，不是失败）
  │     ├─ 读最新 ops-autonomy.json 判断模块开关（模块关 ⇒ 不执行，记 disabled）
  │     ├─ 跑 job（超时隔离；单 job 抛错不拖垮其它）
  │     ├─ 记一行审计（kind=tick.job）
  │     └─ 释放锁
  │
  ├─ 落 ops-tickd.json（最近 50 次 + 每 job 上次状态）
  ├─ 记 tick.start / tick.end 审计
  └─ 退出码：0 无失败 / 3 有 job 失败 / 2 参数错
```

三个 job 各自做什么：

| job | 读 | 写 | 闸门 |
|---|---|---|---|
| `queue-notify` | `ops-queue.json`、`ops-notify-state.json` | 本地 outbox、`processed[]` | 模块开关 |
| `self-heal` | `ops-autonomy.json`、`ops-locks/*` | 状态文件/目录（ensure）、过期锁（repair） | ensure 永远执行；repair 需 `mode=act` **且** `auto.selfHeal=true` |
| `daily-report` | 档位、状态文件、队列统计、告警条数 | `ops-reports/<日期>.md` | 模块开关；内容相同则不写 |

## 3. 闸门顺序（从宽到严）

1. **模块开关**（`ops-autonomy.json` 的 `modules.<id>`）——关掉整个 job；
   每轮重读，所以常驻 tickd 也能感知运行期开关变化。
2. **单例锁**——同一 job 不并发；锁过期可抢占（并记 `stale` 标记）。
3. **自动动作闸**（`isAutoAllowed`）——只有修复类动作需要，双闸：`mode=act` 且 `auto.<action>=true`。

判据 fail-safe：**任何一处缺失/损坏/不是显式 `true`，都按"关"处理**。宁可少做一次自动动作。

## 4. 为什么切成这三层

- **调度层**决定"何时跑"，但它**无权**决定"能不能动手" —— 否则改个 interval 就等于放宽了权限。
- **自主层**是唯一写开关的地方，写盘必须带 `by`/`why` 并落审计，于是"谁在什么时候放宽了闸门"有据可查。
- **通知层**是唯一"出机器"的一层。默认只写本地文件，就是要让"发出去"变成一个**显式选择**。

## 5. 与外部世界的接口

- 进：`ops-queue.json`（你或你的业务写）、命令行参数、环境变量（`OPS_CORE_HOME` / `DSH_HOME`）。
- 出：`ops-reports/*.md`、`ops-audit/*.jsonl`、`ops-notify-outbox.jsonl`、`ops-alert.log`；
  若要真发通知，由调用方注入 `webhookNotifier`（URL 不在仓里）。
- 不碰：宿主 home 的会话/记忆/看板/凭据；不做进程管理；不做跨机。
