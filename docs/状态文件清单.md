# 状态文件清单（这个包会往你的目录里写什么）

> **本文的用途**：跑起来之后，`<home>` 下会多出一堆 `ops-*` 文件。这份清单回答四个问题——
> **谁写的、删了会怎样、要不要备份、能不能带出机器**。
>
> **口径对齐**：本文与《复刻手册》的 `01-状态文件清单.md`（宿主 home 的那份）**同一套判定口径**
> （谁产生 / 里面是什么 / 删了会怎样 / 备份等级 / 能否出机器）。两份清单管的是**不同的文件集合**，
> 冲突时**以手册为准**，差异见 §6。
>
> **单一数据源**：表里的条目与 `src/state-files.mjs` 的 `STATE_FILES` 一一对应；
> `ops-tickd --state` 与日报的健康检查都用同一张表。

---

## 0. 一句话

所有 `ops-*` 状态都在**一个根目录**下（`--home` > `OPS_CORE_HOME` > `DSH_HOME` > `~/.dsh`）。
**默认落在 `~/.dsh`，和宿主 home 是同一个目录**——所以本文最重要的一句是：
**它们只是"多出来的几个 `ops-*` 文件"，不会替换、也不会修改宿主的任何文件。**

```
<home>/
├── ops-autonomy.json          ← 自主矩阵（放行记录，删了等于丢历史）
├── ops-tickd.json             ← 调度状态（最近 50 次）
├── ops-queue.json             ← 待通知队列（唯一由你喂数据）
├── ops-notify-state.json      ← 通知去重表
├── ops-notify-outbox.jsonl    ← 通知产物
├── ops-alert.log              ← 组件自身告警
├── ops-heal-log.jsonl         ← 自愈流水
├── ops-audit/<年-月>.jsonl    ← 审计流水（哈希链，命根子）
├── ops-reports/<日期>.md      ← 日报
├── ops-locks/*.lock           ← 单例锁
└── ops-changelog/<年-月>.md   ← 变更流水
```

## 1. 总表

| 路径 | 谁产生的 | 里面是什么 | 删了会怎样 | 备份 | 能出机器吗 |
|---|---|---|---|---|---|
| `ops-autonomy.json` | `ops-autonomy` / `ops-tickd` | 档位（observe/report/act）+ 模块开关 + `auto.*` 开关 + job 级覆盖 | 下次自动建默认（**全关 / observe**）；**丢的是你的放行记录与 `by`/`why`** | **P1**（纯文本、几 KB） | ✅ 但含操作者署名 |
| `ops-tickd.json` | `ops-tickd` | 最近 50 次 tick 的读数 + 每个 job 的上次状态/计数 | 自动建空状态；只影响"上次跑到哪"的参考值 | ❌ | ✅ |
| `ops-queue.json` | **你 / 你的业务** | `{ items: [{ id, level, message, createdAt }] }` | 自动建空队列（**未处理的通知条目丢了**） | 按需 | ✅ 看内容（可能含业务信息） |
| `ops-notify-state.json` | `queue-notify` job | 已发过的 queue item id（`processed[]`，上限 500）+ `lastRunAt` | 自动建空表 ⇒ **历史通知会被重发** | P2 | ✅ |
| `ops-notify-outbox.jsonl` | `queue-notify` job（file 适配器） | 一行一条本该发出去的通知 JSON | 是**产物**不是状态；删了只丢"发过什么"的记录 | ❌ | ✅ 看内容 |
| `ops-alert.log` | `alert.mjs` | 一行一条 JSON（warn/error），骨架自身故障 | 是产物；首次告警时重建 | ❌ | ✅（含本机路径时脱敏） |
| `ops-audit/<年-月>.jsonl` | 所有写动作（`audit.mjs`） | append-only 审计流水，每条带 `prev` + `hash` | **别删**：它是追责与排障的唯一凭据，删了**无法重建** | **P0（本包内）** | ✅ 但含操作者署名与路径，外发前脱敏 |
| `ops-reports/<日期>.md` | `daily-report` job | 日报：档位 / 上次 job 状态 / 状态文件健康 / 队列统计 / 告警条数 | 可重建（下一轮重建当天那份） | ❌ | ✅ |
| `ops-locks/*.lock` | 调度器 / `store.mjs` | 单例锁（`pid` / `at` / `ttlMs` / `runId`） | 可重建；进程崩溃会留过期锁（`self-heal` 清，需双闸） | ❌ | ❌（含 pid） |
| `ops-heal-log.jsonl` | `self-heal` job | 初始化了哪些文件、清了哪些锁 | 是产物；删了丢"谁在什么时候清过锁" | ❌ | ✅ |
| `ops-changelog/<年-月>.md` | `ops-changelog add` | 一句话变更流水（最新在上，带幂等键） | 是产物；删了丢记账 | P2 | ✅（团队协作时建议 `--file` 指到仓库的 CHANGELOG） |

## 2. 本包的两个"命根子"

1. **`ops-audit/`** —— 哈希链是"事后证明系统做过什么"的唯一凭据。
   任何删除/改写都会在 `ops-tickd --state` 的链校验里暴露（报断点行号）。
   **不能重建**：它不是从别的文件推导出来的。
2. **`ops-autonomy.json`** —— 放行记录（谁、什么时候、为什么把闸门放开）。
   删了会回到"全关"，**安全性不会变差，但审计意义上的历史没了**。

## 3. 可以放心删的

`ops-tickd.json`、`ops-reports/`、`ops-alert.log`、`ops-heal-log.jsonl`、`ops-locks/`（别在 tick 正在跑时删）、
`ops-notify-outbox.jsonl`（是产物）。删完下一轮会自动重建。

⚠️ **两个例外**：

- `ops-notify-state.json` 删了会**重发历史通知**；
- `ops-queue.json` 删了会**丢掉还没处理的通知条目**（它是唯一由使用者喂数据的文件）。

## 4. 与宿主 home 的边界（本包不碰什么）

本包**只写**上面那些 `ops-*` 路径，**不读不写**：

- `sessions/`、`_archived-sessions/`（会话正文）
- `memory/`（记忆库）
- `task-board/`（看板账本）
- `profiles/`、`skills/`、`.agent-presets/`、`settings.yaml`
- `.credentials.yaml`（**凭据**：本包从不读、不写、不转发）

这些是**宿主侧的命根子**，处置口径看《复刻手册》`01-状态文件清单.md` §2/§4；
本包的运行**不可能**因为它们缺失而报错，也不会因为本包运行而改动它们。

## 5. 判据（怎么确认状态是健康的）

```sh
node bin/ops-tickd.mjs --state --home <home>
```

它会打印：每个状态文件存在性/字节/能否解析 + 本月审计链是否完整 + 锁清单。
退出码：`0` = 健康；`3` = 有必需件缺失 / 坏 JSON / 审计链断。

日报的 `## 3. 状态文件` 一节用同一张表，所以**日报和 CLI 不会给出两种口径**。

## 6. 与《复刻手册》`01-状态文件清单.md` 的差异对照

| # | 手册 | 本文 | 处置 |
|---|---|---|---|
| 1 | 只讲宿主 home（会话/记忆/看板/配置/凭据） | 只讲本包的 `ops-*` 文件 | **集合不同、不冲突**：宿主文件按手册，`ops-*` 按本文 |
| 2 | home 解析：`$DSH_HOME`（缺省 `~/.dsh`） | `--home` > `OPS_CORE_HOME` > `DSH_HOME` > `~/.dsh` | **本文多两层**（显式参数 + `OPS_CORE_HOME`）。这是刻意设计：让"一次试跑"能完整隔离，连 `DSH_HOME` 都不必覆盖。**判断落点时以实际生效值为准**（`ops-tickd` 第一行会打印 `home=`） |
| 3 | 文件名会随主包版本变（会话日志 `v3` → `v4`） | 只钉 `ops-` 前缀与扩展名，不钉版本号 | 同一条纪律：**按前缀/通配找，别写死** |
| 4 | 凭据只有一处、绝不出机器 | 本包不读不写凭据 | **不冲突**：本包把"出机器"变成一个显式选择（默认只写本地 outbox） |
| 5 | 备份等级 P0/P1/P2 | 沿用同一套等级 | 本包 P0 = `ops-audit/`，P1 = `ops-autonomy.json`，P2 = `ops-notify-state.json` / `ops-changelog/` |

> 如果两份文档真的打架：**以手册为准**（它是宿主层的权威），并把差异补进本节。

## 7. 这张清单什么时候会过期

- 本包升版时若新增/改名状态文件：先改 `src/state-files.mjs`（单一数据源），再同步本文与 README。
- 宿主主包大版本升级：宿主那部分见手册 §8，与本包无关。
- 判断方法不依赖本文：`node bin/ops-tickd.mjs --state` 打印的就是当前真实清单。
